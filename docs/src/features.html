Phase 1

The client lifecycle

Delivered

Sales pipeline

Lead → Qualification → Discovery → Diagnosis → Solution → Proposal → Negotiation → Won
A guarded state machine. A deal cannot skip a stage or move without meeting that stage's requirements, and the rule is enforced in the database — not merely in the interface.
Qualification checklist, discovery capture and diagnosis
Structured records rather than free text, so the reason a deal advanced is legible afterwards.
Kanban board with drag-to-transition
Dragging a card attempts a transition and reports why it was refused, rather than silently reverting.
Solution design and service catalogue
Reusable services with rates and estimates, composed into a priced solution.

Proposals

Versioned proposals with an approval trail
Draft → internal review → approved → sent → accepted. An accepted version is frozen and can never be edited.
Separate authority to approve and to send
The person who approves a proposal is not automatically the person who may send it.

Legal and contracts

Deterministic contract generation from templates
Rendering fails on a missing variable rather than producing a document with a blank in it. Every rendered document records the exact values used.
NDA, MSA, SOW, addendum and amendment types
With parent–child relationships, so an amendment always knows what it amends.
E-signature integration
Zoho Sign, plus a fully functional manual provider so the complete legal workflow runs without a provider account.
Executed-document capture with SHA-256 verification
The signed document is stored and hashed. A file whose bytes no longer match its recorded hash is quarantined and cannot be downloaded.
The legal gate
A client cannot be onboarded until the required agreements are executed and the required payments met. Enforced by a database function, so no code path can bypass it. Overrides are possible, permanent and recorded.

Finance

Payment requirements, invoices and payments
Advance, milestone, final and full requirements, any of which can block onboarding.
Exact decimal money and multi-currency
Money is never a floating-point number. Conversion uses recorded FX rates and returns nothing rather than assuming parity when a rate is missing.

Delivery

Onboarding checklists, projects, workstreams, tasks and deliverables
Provisioned automatically when a deal is won and the legal gate is satisfied.
KPIs with baselines, targets and measurements
Per client and per project, with client-visible flags.
Project health tracking and client reports

Platform foundations

Multi-tenant isolation enforced by the database
Row-level security is enabled and forced on every tenant table, deny-by-default. One customer cannot read another's data even if application code asks for it.
Role-based access control with ownership scopes
133 permissions across 8 roles, each expressible as own / team / organisation.
Complete audit trail and a domain event log
Every consequential action is recorded with who, when, and from which request.
Document management with versioning and immutability
Confidential documents require a separate permission; a denied attempt is itself recorded.
Background worker with retry and backoff

AI assistant

Answers questions about your own data
Eight fixed read-only tools. No generated SQL. Restricted to what the person asking is permitted to see.
The model can never write to a record
Anything it drafts becomes a proposal that a person reviews, edits and approves before it takes effect. Enforced by a database trigger, not by convention.
Every answer shows its sources
The list of tool calls that produced an answer is shown alongside it, so the working can be checked.

Automation engine

WHEN → IF → THEN rules over domain events
A closed set of eleven actions. There is deliberately no “send email” action anywhere in the product.
Loop protection
Chain depth and per-record cooldown, both recorded on every run.
Phase 2

Production readiness

Delivered
Amazon SES email provider New
Full implementation. A rejected sender identity is reported as a configuration fault rather than a temporary one, so the queue stops instead of retrying a broken setup indefinitely.
Browser test suite New
29 tests that drive the real application in a real browser. They verify that every page not only renders but responds to a click — a distinction that matters, because a page whose JavaScript failed looks completely normal and does nothing.
Preflight diagnostic (npm run doctor) New
Checks the database, migrations, seed data, security posture, storage credentials and the AI key against the live services, and reports the actual reason for each failure.
Performance work New
Sign-in identity resolution reduced from five database queries to one; transaction setup from five network round trips to two; rate limiting from four to one. Page response improved from roughly 3.9 seconds to under 0.4.
Runtime version pinned
A deployment on an unsupported Node version now fails loudly rather than warning quietly.
Phase 3

Client portal

Delivered
A separate application for your clients
Six screens: overview, projects, project detail, documents, invoices and reports. Clients see their own work as their delivery team sees it.
Clients can accept or reject deliverables
A rejection must say why. The decision is attributed to the individual, and appears on both timelines.
Per-person permissions
Three independent switches — documents, invoices, approve deliverables — set per person from the client record.
Documents delivered by short-lived signed links
Issued per click and expiring in fifteen minutes, so a link cannot outlive the page it was meant for. Confidential documents are never visible to a client.
Invite and revoke access, with a full record
Clients set their own password from a one-time link; no password is ever generated for them. Revoked access is retained, not deleted — “who could see our invoices, and until when” is a question that gets asked after the fact.

How the boundary is built

The portal reads through 15 dedicated database projections that physically exclude cost, margin, internal notes and AI analysis. Those columns are not hidden or filtered — they do not exist in what the portal can query, so no future mistake in the application can expose them. Portal users hold no internal membership, so every internal security policy denies them by construction.

Phase 4

Revenue retention

Delivered
Renewal engine
Every executed contract with an end date opens a renewal cycle as it approaches its notice window. Each cycle has an owner, a decision and an outcome — renewed, lost, auto-renewed or not renewing.
A lost renewal must record why
The single most useful field in the system. Reasons are counted on the renewals dashboard, so churn becomes something you can act on rather than only observe.
Retention rate and value at risk
Value due in the next 90 days, value currently being worked, and twelve-month retention as a share of value that actually reached a decision.
Pipeline forecast
Weighted value by expected close month, shown beside unweighted open value and already-committed value — because a single weighted figure invites more confidence than the method supports.
Delivery profitability
Invoiced revenue less recorded cost, per project, with hours used against estimate. Restricted to those permitted to see cost. A project with nothing invoiced reports “no data” rather than a misleading negative margin.

On the honesty of the numbers

Amounts that cannot be converted to your base currency — because no exchange rate has been loaded — are excluded from every total and counted, with the report saying so explicitly. A total that quietly absorbs an unconverted currency looks exactly like a correct one, which makes it worse than no total at all.

Phase 5

Integrations

Built · unverified
No-code automation builder
A visual WHEN → IF → THEN editor. Create, edit, activate, pause and delete rules without a developer. Switching a rule on is a separate action from editing it, and the two are recorded separately.
Slack notifications
Alerts posted to a channel. Every message is recorded before it is attempted, so one lost to an outage leaves a trace rather than disappearing.
WhatsApp notifications
Via the Meta Cloud API, using an approved message template. The system refuses to send without one rather than attempting it, because a non-template message outside the 24-hour window is accepted by the API and never delivered — a failure that looks identical to success.
Gmail and Microsoft 365 mailbox sync
Client email appears on the client's timeline automatically. Read-only access is requested; the system asks for no permission to send, modify or delete.

Three rules that hold by construction

  • Incoming email is data, never an instruction. No automation can be triggered by it, and the AI assistant reads it through the same restricted tools as everything else.
  • Nothing is ever auto-replied. There is no path from a received message to a sent one that does not pass through a person.
  • Only mail exchanged with a known contact is stored. A mailbox belongs to an individual and most of its contents are none of the platform's business.
